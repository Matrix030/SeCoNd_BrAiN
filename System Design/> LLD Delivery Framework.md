# LLD Delivery Framework

A step-by-step framework for structuring a low-level design interview in ~35 minutes.

---

## Why a Framework?

Most candidates fail not from lack of knowledge, but poor time management:
- **Too fast**: Dive into code, get lost in edge cases before showing structure.
- **Too slow**: Over-detail setup, run out of time before meaningful design.

> [!tip] Follow the interviewer
> If they pull you off-framework, follow their lead — but gently guide back to cover the important bits.

---

## The Five Phases

| Phase                                                          | Time       | Focus                                       |
| -------------------------------------------------------------- | ---------- | ------------------------------------------- |
| [[LLD - Requirements\|Requirements]]                           | ~5 min     | Turn a vague prompt into a concrete spec    |
| [[LLD - Entities and Relationships\|Entities & Relationships]] | ~3 min     | Identify core objects and ownership         |
| [[LLD - Class Design\|Class Design]]                           | ~10-15 min | Define state and behavior per class         |
| [[LLD - Implementation\|Implementation]]                       | ~10 min    | Pseudo-code the key methods                 |
| [[LLD - Extensibility\|Extensibility]]                         | ~5 min     | Show your design handles follow-ups cleanly |
